# Spec: v2-api

Status: Ready for Implementation
Created: 2026-10-17

## Goal

Every endpoint of SDD §7.1 answers under `/api/v1` in the `netray lens` process (the apex until the cutover), served by `netray-web`'s API router (SDD §3.1) that lens nests ahead of its SPA fallback, and described by one OpenAPI 3.1 document that is generated by utoipa, served at `/api/v1/openapi.json` with an interactive docs page at `/api/v1/docs`, and committed as `tests/fixtures/contracts/api-v1.openapi.json`. A test validates at least one success and one error response of every path against the committed document; a contract test fails when the generated document removes or retypes a path, method, status, property or enum value of the committed one. The stored `RunCheck` carries its findings and evidence references, outside the fingerprint and the diff. Domain and entry endpoints serve what `netray-store` holds, byte for byte; `POST /domains/{domain}/runs` goes through lens's admission coordinator of `v2-admission`; inspector, email and `ip.` endpoints call the same job functions as today's service routes, with the same validation and limits. `curl ip.netray.info` answers the caller's address as text, tested in the gate. A `tests/repo` check fails when `crates/web/src/api` names a scoring or diff function. Every V1 API, the lens goldens and the contract goldens are unchanged. This is SDD Phase 3, criteria V3.1–V3.4 (R5, R34, S23).

## Non-goals

- Removing, redirecting or answering `410` for any V1 API or `ip.` route (V5.3, `v2-cutover`).
- Host routing, `netray serve`, one `netray.toml`, the `netray_` metrics namespace (S1, S10, S11; cutover).
- Any UI besides v1's own docs page (requirement 35): the result page, inspector pages (Phase 4). The inspector page's server-rendered job route is `v2-inspectors`'; this feature only offers it the job functions and limiters.
- YAML, TOML or CSV output under v1 (S23: JSON and plain text only).
- Request options on runs (`dkim_selectors`) or DKIM selectors on `/email/inspect`.
- A `starttls` field on `/tls/inspect` (decision log).
- A streaming mechanism of its own: v1's `section` events are the `Section` events of v2-admission's `RunStream` (its requirement 21), forwarded as they arrive.
- A release of its own; ships in local `0.30.0` (operator, 2026-10-17).

## Requirements

1. API v1 lives in `netray-web`, module `crates/web/src/api/`, which exposes `api::router(ApiState) -> axum::Router` (X1). There is no `netray-api` crate.
   - `netray-web` gains the dependencies it does not yet have among axum, utoipa, utoipa-axum, `netray-store`, `netray-engine`, `netray-model` and the five module crates (SDD §3.1's edges). It never depends on `lens`.
   - `tests/repo/test_web_crate.sh`, under `ADLC-Test-Change`, lifts whichever of its three Phase 4a guards still stands when this phase starts: a `Router` is allowed under `crates/web/src/entries/`, `src/pages/` and `src/api/` and still refused elsewhere in `crates/web/src`; axum is allowed as a dependency; `netray` may depend on `netray-web`. Its other checks stay.
   - `ApiState` holds the history store (optional), the catalogue and profiles, the client-address extractor, the `[api]` limiters, the inspector job handles (built over each lens module's own state from `[modules.<inspector>]`, the email slots from `[api.email]`) with their limiters built from `[api.<inspector>]`, the IP module (optional), and a value implementing the trait `api::DomainRuns` (requirement 14).
   - `netray_web::api::DomainRuns` is the one seam from netray-web to lens's validation and admission, used by v1 and by `v2-result-page`'s run POST alike. It is defined here and nowhere else, with netray-web's own types so netray-web names no lens type:
     - `validate(&self, domain: &str) -> Result<String, DomainRefusal>`: the normalised domain, or a refusal with code `DOMAIN_INVALID` and its message (`validate_domain` produces no other refusal);
     - `start(&self, domain: &str, client: IpAddr, trigger: RunTrigger, prefetch: bool) -> RunStart` (async): `RunTrigger` is `Visit | Recheck | Api`; `RunStart` is `Admitted(RunEvents)`, `Refused(RunRefusal)` or `NotStarted`; `RunRefusal` is `{reason: Throttle | Budget | IpLimit | GlobalLimit | Slots, retry_after_s: u64, last_run_ago_s: Option<u64>, last_incomplete: bool}`; `RunEvents` is a stream of `RunEvent::Section(netray_engine::SectionEvent)`, `RunEvent::Done(netray_model::Run)` and `RunEvent::Recorded(Option<netray_store::Recorded>)`, in v2-admission's order, and dropping it never cancels the run.
     - lens implements `start` as v2-admission requirement 20 asks of a caller without a cache step: `check_limits(client)`, then `admit(domain, client, trigger, prefetch)`, mapping `Admit`, `Refusal`, `Trigger` and the `RunStream` onto these types one to one (`Done` keeps only the `Run`). It reads no cache window: a caller that has one applies it before `start`.
     - `prefetch` comes from `netray_common::prefetch::is_prefetch` over the request headers, and `client` from the client-address extractor of requirement 9.
   - `crates/netray` builds the module-side parts (inspector job handles, the `Arc<IpModule>` it already holds) and passes them to `lens::run_with`. lens adds the store, its `ip_extractor` and its `DomainRuns` implementation (`validate` in Phase 1, `start` in Phase 3) over `crates/lens/src/admission.rs`, and nests `api::router` under `/api/v1` inside its middleware stack (`crates/lens/src/lib.rs:162-200`), ahead of `spa::handler`, until `v2-cutover` mounts it in `netray serve`.
   - lens names no module crate in its manifest or source: `test_lens_names_no_module.sh` stays green unchanged.
2. The v1 document is OpenAPI 3.1, generated by utoipa 5 with `utoipa-axum`, `info.title` "netray API", `info.version` the workspace version, every server path prefixed `/api/v1`. `GET /api/v1/openapi.json` serves it and `GET /api/v1/docs` renders it (requirement 35), both exempt from rate limiting. Every endpoint of §7.1 carries `#[utoipa::path]`; every request, response and SSE event type derives `ToSchema`; the error shape is one component (`netray_common::error::ErrorResponse`) referenced by `$ref`. No schema in the document is untyped (an empty schema, a schema with only annotations and no `type`, `$ref`, `oneOf`/`anyOf`/`allOf`, `enum` or `const`, or `type: object` with neither `properties` nor a typed `additionalProperties`); a test walks the document and fails on one.
3. `netray-model` (`Run`, `RunSection`, `SectionKind`, `RunCheck`, `CheckId`, `BlockId`, `Status`, `Grade`, `Protocol`, `Severity`, `FixOwner`, `Block`, `Shape`, `Value`, `Record`, `Node`, `Diff` and its parts) and `netray-engine` (`CheckSpec`, `Profile`, `SectionWeights`) derive `ToSchema` unconditionally; `CheckSpec` and `Profile` gain `Serialize`. `CheckId` and `BlockId` are documented as strings. Apart from requirement 4's fields, no serialised form changes: every existing golden stays byte-identical.
4. `RunCheck` gains `findings: Vec<String>` and `evidence: Vec<BlockId>`, each `#[serde(default, skip_serializing_if = "Vec::is_empty")]` (X2).
   - `lens::history::build_run` copies a measured check's `messages` into `findings` and its `evidence` into `evidence`, in their order. The checks it fills from the catalogue for a not-applicable or incomplete section carry neither.
   - `fingerprint` and `diff` never read either field: two runs that differ only in them have equal fingerprints and an empty diff, so `record` answers `Identical`.
   - A stored run without the fields (every entry recorded before this phase) parses with both empty.
   - In the document both are optional (absent from `required`).
   - Test struct literals of `RunCheck` gain the fields; a test that pins a lens-built stored run's JSON changes only by the added fields, under `ADLC-Test-Change`.
5. `tests/fixtures/contracts/api-v1.openapi.json` is the committed contract. A test in `netray-web` fails when the generated document, ignoring `info.version`, lacks a path, method, parameter or response status of the committed one; lacks a schema property, `enum` value, `oneOf`/`anyOf` variant (matched by content, not by index) or component; changes a property's or parameter's `type`, `format`, `items`, `additionalProperties` or `$ref` target, including adding or removing one of them; drops a response property from `required`; or adds a request property to `required` or makes a parameter required. A second assertion fails when the generated document differs from the committed one in any other way, naming `UPDATE_GOLDEN=1 cargo test -p netray-web --test openapi_contract`; that command rewrites the fixture only when the first check passes. Removing or retyping something can therefore only be committed by editing the fixture by hand, which needs `ADLC-Test-Change`.
6. A test validates every endpoint's responses against the committed document: the status is documented for the path and method, and the body validates against its schema with `$ref`s resolved. SSE events validate per event type; a `text/plain` answer is checked for content type only. The validator is the `jsonschema` crate as a dev-dependency (default, not interviewed). Every path and method of the document has at least one validated 2xx case and one validated error case; a coverage test fails on a path without them.
7. Every non-2xx v1 answer carries the error shape. The codes, each stable: `DOMAIN_INVALID` 400, `INVALID_INPUT` 400, `BATCH_TOO_MANY` 400, `TARGET_BLOCKED` 403 (an inspector's target policy refused the target: tlsight's `BlockedTarget`, spectra's `BlockedTarget`, each `403` today), `NOT_FOUND` 404, `GONE` 410, `RATE_LIMITED`, `THROTTLED`, `BUDGET_EXHAUSTED` and `BUSY` 429 with `Retry-After`, `METHOD_NOT_ALLOWED` 405 (a known path with another method), `PAYLOAD_TOO_LARGE` 413 (lens's 8 KiB body limit, answered for a v1 path in the error shape), `INTERNAL_ERROR` 500, `UNAVAILABLE` 503 with a message that names the switched-off or full part, `PREFETCH_REFUSED` 503 with `Cache-Control: no-store` (codes default, not interviewed, following lens's `AppError` codes, `crates/lens/src/error.rs:61-72`, and v2-admission's `PREFETCH_REFUSED`; `TARGET_BLOCKED` keeps the status tlsight and spectra answer today). An unknown path under `/api/v1/`, `/api/v1/` itself included, answers `404 NOT_FOUND` as JSON, never the SPA index, and an extractor rejection (invalid UTF-8 in a path segment) answers `400 INVALID_INPUT` in the error shape, except an entry ID, which is malformed (`404`, requirement 13); a path outside `/api/v1/` still reaches the SPA.
